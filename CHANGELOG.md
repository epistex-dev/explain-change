# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project follows
[Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added
- A sixth colour theme, `midnight`, in the colours of the intro video: glassy gradient surfaces, a lit ring and faint violet and blue glows in the corners of the page. It is on the session page, the change page and the flow page, and keeps the contrast of the other themes.

### Changed
- `midnight` is now the theme a page opens in when `render.py` gets no `--theme` and the reader has no stored pick. A stored pick still wins, and the five earlier themes stay in the Appearance picker. The README screenshots show midnight.
- The error for an unknown `--theme` now names six ids.
- The two reference folders are one: `skills/explain-change/reference/examples` and `reference/ui` moved to `skills/explain-change/references/examples` and `references/ui`. The duplicate `reference/ui/LICENSES.txt` is gone (`assets/ui/LICENSES.txt` stays).
- The test suite (`tests/`, with `red_check.py`) and the design notes (`docs/design.md`, was `DESIGN.md`) moved out of `skills/explain-change/`, so an install ships only the skill. Run the tests with `python3 -m unittest discover -s tests`.

### Removed
- The v1 report page and Mermaid (`mermaid.min.js`, 5.5 MB). A change doc with `version` 1 or no `version` now makes `validate.py` and `render.py` exit 1 with `error: explain-change v1 docs are no longer supported; write version 2 (references/explain-schema.md)`. Docs with `version: 2` are unaffected.
- `docs/images/intro.webp` (7.6 MB). The README intro is the AVIF, linked to the mp4.
- Seven README screenshots that were byte-identical copies of ones in `docs/images/themes/` (2.8 MB): `hero.png`, `session-1440x900.png`, `session-800x900.png` and the folder `no-transcript/`.

## [0.1.0] - 2026-11-05

### Added
- `explain-change` skill: collects a diff and the agent session, checks every quote, command and cited line, and renders one offline HTML page (schema v2) in Vietnamese (`vi`) or English (`en`).
- Five-block page: request and result, where it changed (system map), how the new logic runs, why this way, evidence checked. Grounding checks cover quotes against the session transcript, tool-call evidence and redaction of credentials; a short label such as `mk:` inside a CSS name (`--mk:`, `.mk:hover`) is not learned as a secret, while `password=`, `db_password=` and `--token=` still are.
- Bundled sample doc (`reference/examples/password-autofill.v2.json`) and a red-check script that proves each guard is tested, with sharded, time-limited runs.
- Plugin and marketplace manifests for `/plugin marketplace add epistex-dev/explain-change`, a `gemini-extension.json` (Gemini CLI extension) and a portable `plugin.json` (Agent Plugins manifest, read by Codex).
- `install.sh`: installs the skill for Claude Code, Codex, Gemini CLI, Copilot, Cursor, OpenCode, Goose, Amp, Kiro, Windsurf, Cline and Roo (`--harness`, `--copy`, `--project`, `--uninstall`, `--dry-run`, `--force`), with an Install section in the README, one row per harness, and tests for the installer and the manifests.
- Transcript readers for GitHub Copilot CLI, Codex, OpenCode (database and JSON tree), Gemini CLI, Cursor CLI and Cursor IDE, each limited to its harness's own transcript folder, with fixtures and guards in the red check. `collect.py`, `validate.py` and `render.py` take any of them for change docs and session docs: `--transcript` detects the format, `--format auto|claude|copilot|codex|opencode|gemini|cursor-cli|cursor-ide` names it, and a file in none of them and outside every harness folder exits 1 with one line naming the formats (a directory exits 2). `collect.py` lists the sessions of the repo's folder labelled by harness.
- A README and `SKILL.md` table of the supported harnesses and their transcript folders, kept equal to the readers by a test. `SKILL.md` names no single harness: the cold-read gate uses a fresh subagent, else the command in `EXPLAIN_COLDREAD_CMD`, else is skipped and the final reply says so.
- A shell call whose output or exit code a harness did not record has an unknown result: it cannot back a `passed` run or a `done`, and the validator says why. Text a harness injected into the user channel never matches a request quote.
- Session mode: `explain-session/1` docs, `collect.py --session`, and a swimlane page (`render.py` on a session doc) with a strip, one lane per theme, a side panel that opens on what the agent decided (irreversible choices always listed, reversible ones in an accordion) and the outward actions, and a link to each theme's change page. A compact band puts the summary and Needs you side by side so all lanes show on a 1440 x 900 screen. The page has `header` and `nav` landmarks, and an open count bubble stays pressed and keeps focus when the lanes are laid out again. Real deletes show as outward actions; deletes under `/tmp/` or `$TMPDIR` show as one count line. A worktree made by `git worktree add` in the transcript counts as its repo.
- Five colour themes (navy, ocean, plum, graphite, pearl) with an "Appearance" picker in the header of the session page and the change page. The pick is remembered in one `localStorage` key, so it carries across both pages, and `render.py --theme <id>` sets the theme a page opens in (an unknown id exits 1 with one line naming the valid ids). Before/after blocks, map nodes, edges and chips follow the theme, and every theme keeps text at 4.5:1 and rings at 3:1.
- A change doc and a session doc work with no readable transcript (a harness without a reader, a missing or unreadable file, a run outside any agent session). The doc gives `"transcript_unavailable": "<reason>"`, a single line of at most 200 characters; `validate.py` and `render.py` (without `--transcript`) refuse a doc with neither a transcript nor a reason, and a doc with both, and still check git, diff, counts, file coverage, cited code and secrets. A credential in the doc's own quotes is refused wherever the doc repeats it. The change page shows a short badge "Not checked against the session", gives the reason as one line in the Evidence tab, and marks runs as the agent's own account; the session page carries "Not checked against the session: <reason>" beside its status key and shows each outward count as the agent's own, once. `collect.py --session` with no session names this path.
- Flow mode: `explain-flow/1`, a doc that explains how an existing flow of the code works, with no diff and no agent session (`references/explain-flow-schema.md`). `collect.py --flow [--path …] [--slug …]` prints HEAD, the modules and the files, and never exits 3. `validate.py` reads every source from the doc's commit (`git show <commit>:<path>`) and checks its lines and excerpt, the structure of parts, steps, branches and errors, and that the visible text holds no code and no secret. The no-code rule accepts a bare file, product or domain name (`README.md`, `Node.js`, `example.com`) or a price such as `$5.50`, and refuses an assignment or comparison (`x = y + 1`, `a > b`), a statement (`return foo`, `lambda x: x+1`, a text ending in `:`) and brackets (`[1, 2]`, `arr[0]`). A part may give an `icon` from a fixed list (the sprite icons plus `file-search`) and a step may list `reads`, the parts it takes input from. A field of the wrong type, or text with a lone surrogate, is one line from `validate.py` and `render.py`, never a traceback. The example `reference/examples/claim-check.flow.json` explains how a claim is checked.
- The flow page: `render.py` on an `explain-flow/1` doc writes one offline page (question and summary, counts, numbered route, map of the parts, one panel per step with branches and error exits, all steps in the HTML without JS, `#step-N`, the five themes, `vi` and `en`, a footer naming the checked commit); a doc with an unknown `kind` exits 1 with one line. The map draws its lines from the doc, routed around the cards with clear arrowheads; under 1100 px each card says where it hands over instead. The page names each concept one way in `en` and `vi`: error exits, branch points, parts, problem list.
- A 30 second intro clip at the top of the README (`docs/media/intro.mp4`, animated AVIF preview with an animated WebP fallback in `docs/images/`), with its HyperFrames project and render script in `docs/intro/`; it uses only the bundled sample data.
- Community files: a contributing guide, a security policy, issue templates and a pull request template.
